### Legal — what’s actually needed now

For a **personal artist static site** on GitHub Pages at this stage:

| Need? | Item | When it becomes real |
| --- | --- | --- |
| **Maybe** | Short **Privacy** page | If you keep **embeds** (Apple Music / Spotify), add **analytics**, or a **contact form** that collects email |
| **Maybe** | One-line **cookie / embeds note** in footer or on Privacy | Third-party players set their own cookies; honesty > banner theater if no first-party tracking |
| **Skip now** | Heavy ToS, returns, shipping, cookie CMP walls, GDPR cookie consents for marketing | No e-commerce, no mailing list, no ads |
| **Skip now** | Full business-address / phone block like a studio practice | You’re not selling services as a firm |

**Telha Clarke’s privacy page as a model — take / leave**

- **Take:** Short sections — what you collect · how (e.g. Analytics / embeds) · purpose · sharing (none/sold) · contact for questions · “we may update”. Plain language.
- **Leave / overkill for Jy:** Registered office, phone, “architectural and design services” framing, company-registration tone. Map hers to: *site operator name + contact email + “embeds/analytics only if present.”*
- **Practical minimum if Apple Music embed stays and no analytics:** a ½-page Privacy that says (1) no account system, (2) third-party players may process data under their policies, (3) contact email for requests. Add Analytics bullets only if you turn it on later.

## B. Hub / artistic eras research

### How Lady Gaga’s Music hub works (checked)

- **Index first:** `/us-en/music` is a **reverse-chronological release list** (albums, singles, soundtrack projects) — catalog, not a single immersive scroll.
- **Entry points:** each title routes to its **own world page** (e.g. `/music/mayhem`, `/music/chromatica`).
- **Per-world page:** distinct artwork/title identity → intro/overview → **Streams** CTA row (Apple, Spotify, etc.) → video / deeper media. Chromatica shows era storytelling; MAYHEM leans artwork + streams + video.
- **Chronologic vs visual:** chronology on the hub; **visual identity lives inside** each release page — not one recolored template sold as “eras.”
- **CTA language:** title/artwork as the click target into that world; streams are secondary CTAs *inside* the world (not on the hub row alone).
- **Shop is separate** — music discovery ≠ commerce. Useful parallel: Jy can keep hub ≠ store forever.

### Comparable hub patterns (URLs checked)

1. **[fossora.com](https://www.fossora.com/) (Björk)** — *single-era immersive world*: nonlinear exploration, manifesto voice, media nested in a distinct visual system. Strong “enter this album’s physics” lesson for Dysphoria-like gates; **not** a multi-era index by itself.
2. **[taylorswift.com/swiftiearchive](https://www.taylorswift.com/swiftiearchive/)** — explicit **“guide through the eras”** framing: archive/hub that promises many worlds behind one door. Good language model for a multi-era artist index (even if production scale differs).

*(Public case-study pattern, not re-fetched as live Feist product: Feist-style dual timeline — large career “slices” + persistent mini-timeline — is another known multi-era nav; treat as inspiration only unless Jy wants that interaction cost.)*

### 3–5 concrete hub concept options for Jy

| # | Concept | Sketch |
| --- | --- | --- |
| **1. Era tiles** | Home = grid/stack of **distinct visual thumbnails** (Dysphoria B&W cover language; later EHW / A+I get their own stills). Tap → era route. | Closest to i-D “each page different” *previewed at hub*. |
| **2. Chronological spine** | Vertical timeline: year/label → short line → “Enter …”. Dysphoria first live; empty slots or “soon” for EHW, Authenticity + Imitation. | Clear history; quieter visually. |
| **3. Gate language (current DNA)** | Keep **“Enter Dysphoria”** pattern; hub is a sequence of gates (one live, others locked/ghost). Matches existing `index.html` CTA. | Lowest conceptual jump from alpha. |
| **4. Index vs immersive split** | Hub stays **fast index** (Gaga-like list or tiles); immersion only *inside* eras (fossora/Dysphoria depth). | Best mobile perf + editability. |
| **5. Hybrid spine + tile** | Left/top: year spine; right/main: large era tile that swaps identity on select. | Rich, higher design + Android QA cost. |

### Pros / cons (tied to Jy constraints)

| Option | Distinct era IDs (i-D-like) | Mobile-first / Android QA | Extensibility (add eras) | Content editability |
| --- | --- | --- | --- | --- |
| **1 Tiles** | **Strong** — each thumb can be a different world | Good if tiles are static images + simple links | Add a tile + route | Easy (image + label + href in JSON) |
| **2 Spine** | Medium — identity mostly after click | **Very safe** (mostly text/flow) | Append row | Easiest |
| **3 Gates** | Strong once inside; hub can feel samey if all gates share one chrome | Gate motion needs Android scrub care (already a Dysphoria lesson) | New gate component per era | Medium (motion + copy) |
| **4 Index→immersive** | **Strong where it matters** (inside eras) | **Best** — hub stays light | Add list item | Easy hub; eras keep JSON |
| **5 Hybrid** | Strong | **Highest QA risk** | Flexible but complex | Harder for zero-code edits |

### Recommended default + decision for Jy

**Default recommendation: Option 4 + Option 1 skin** — a **light index hub** with **era tiles** (distinct stills, not one template), each CTA using **gate language** already loved (`Enter Dysphoria` → later `Enter EHW`, etc.). Immersion stays inside era pages (Dysphoria pattern). Do **not** build a fossora-scale multi-world WebGL hub for v1.

**Decision Jy needs to make:**

1. **Hub metaphor:** *tiles*, *timeline spine*, or *gates-only* (or hybrid)?
2. **Unfinished eras:** hide until ready · show “coming” ghost tiles · or list names only?
3. **Home weight:** hub-first (eras) vs person-first (About teaser above eras)? Recommendation: **eras first**, About in chrome — matches portfolio-of-worlds, still “know Jy” via About one tap away.
